1 Exercise 1

Analyze the quip “One person’s program is another program’s data.”, from its origins (“Quod ali cibus est aliis fuat acre venenum.” and “One man’s meat is another man’s poison.”) to its significance here.

In a letter to Robert Hooke…

“If I have seen further it is by standing on the shoulders of Giants” - Isaac Newton

Introduction to Exercise:

In order to solve this exercise, we started discussing the origins of the quote, and extrapolated its meaning to the aforementioned quip and what it says about the ‘collaborative’ nature of programming.

Answer:

Firstly, let’s break down the phrase “One man’s meat is another man’s poison.” This basically refers to the versatility of certain items. To take the quotation quite literally, it’s like how I, a vegetarian, don’t take meat because it makes me feel sluggish and lethargic, but for some people, meat is a godsend. Meat is ‘versatile’ because it functions as an item of pleasure for some people, but as an inedible item for vegetarians like me.

Okay, now let’s apply this concept to programming.

Programs, like meat, are also versatile in many ways! Some programmers write good programs, like a program that counts sheep. However, this sheep counting program could be data used within a grander scheme of things, such as an app that helps people sleep.

Or, more realistically, us programming students going on GitHub or Stack Overflow to refer to good programs and code to advance our understanding and build our own quirky projects.

In essence, and also to jive with our chosen quote, programs are versatile and can be used to do things different (“another program’s data”) from their previously intended function (“One person’s program).

2 Exercise 2

Given a source program and its input, an interpreter executes source_program on input:

run interpreter (source_program, input) = output

Typically, we run source_program on several inputs, not just one. So it is a good idea to specialize interpreter with respect to a given source_program.

To be concrete, say that interpreter is an interpreter for Python written in OCaml, and that the S-m-n function specializes a program written in OCaml into another program written in OCaml.

Questions:

  • In which language is source_program written?.

Okay, since Prof Danvy likes connecting Philosophy to Computer Science, let’s reason our answer in a logical, philosophical way that would make Aristotle proud.

Premise 1: An interpreter executes source programs.
Premise 2: The language an interpreter executes should be the same as the language the source program is written in.
Premise 3: The interpreter executes Python.

Conclusion: Hence, the language the source_program is written in is Python.

  • Apply the S-1-1 function appropriately to specialize the interpreter with respect to source_program, and characterize its result.

We first instantiate the characteristic equations:

run p (x, y) = result
S-1-1 (p, x) = p_x
   run p_x y = result

with:

  • interpreter for p
  • source_program for x
  • input for y
  • output for result

The result reads:

run interpreter (source_program, input) = output
S-1-1 (interpreter, source_program) = interpreter_source_program
   run interpreter_source_program input = output

And then the questions are:

  • in which language is interpreter_source_program written?
  • what is interpreter_source_program, i.e., what does it do when it is executed?
  • what is the relation between source_program and interpreter_source_program?
  1. interpreter_source_program must be written in the same language as the interpreter, as interpreter_source_program is simply a specialised version of the source_program based on the interpreter. Hence, interpreter_source_program must be written in OCaml.
  2. When interpreter_source_program is executed, it evaluates the input and gives the output. This result would be the same as if we were to run the interpreter with the source_program and said input.
  3. To me, this mimics the structure of a compiled program, where instead of the interpreter having to interpret the source_program every time we want to run it, the source_program simply becomes an executable. Instead of running the interpreter for the source_progran every time, interpreter_source_program becomes a shortcut on which we can run any input.

3 Exercise 3: Write down the four causes of a partial evaluator.

Introduction to Exercise:

"Patience is bitter, but its fruit is sweet." - Aristotle.

This exercise requires an in-depth understanding of what a partial evaluator is and how to communicate its function. In order to achieve this, we went through the lecture notes and had to understand the S-m-n function and its various steps involved. Our group developed several analogies and tried to connect it to the technical terms and steps in order to grasp the concepts. This took us quite some time but as our buddy Aristotle said, the fruit of finally understanding this theorem and its role was very very sweet indeed.

A partial evaluator evaluates a part of a program and outputs a new program which only consists of the remainder of the program based on a particular input. The part of the program it evaluates depends on the input. Using the input, it evaluates the program to whatever extent it can with the information it has. Now, to evaluate the remainder of the program, we require more input. The partially evaluated program is known as the residual program.

In order to make the execution of a program more efficient, a partial evaluator acts on a part of the source program with respect to its given input and integrates it into a residual program.

  • Final cause: Make the execution of a program more efficient
  • Material cause: Input and source program
  • Formal cause: Integrates a part of the source program into a new program that is a residual program
  • Efficient cause: A partial evaluator acts on a part of the source program

Takeaways:

This exercise increased our awareness of what a partial evaluator does and how it functions. As such, we are able to understand how a partial evaluator fits within the bigger picture of making programs more efficient and understanding the concept of specialisation.
