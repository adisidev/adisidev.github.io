Au contraire, that is exactly what we can do! We return v * a (that is, the payload of the leaf multipled by the accumulator) whenever we find a leaf. 2.7 Direction of Traversal of Binary Trees

The node case is always structured like so, (visit t1 (visit t2 a)).

Hence, in this case, node t2 is visited first and node t1 is visited next. Therefore, the right node is visited first, and then the left node is visited second.

Even in the implementations through binary_tree_fold, the node case takes the form ih1 (ih2 a).

Even in the given implementation, mult_v5, we see that the node case is visit t1 * visit t2. Since functions arguments are evaluated from right to left (knowledge we now know thanks to our mid-term project about the underlying determinism of OCaml), visit t2 would be evaluated first followed by visit t1.

And since, the solutions are meant to be structually recursive, the trees are traversed depth-first, of course.

4.8 The Big Picture Stuff

Overall:

  • FOO FIFO and BAR FIFO both traverse the tree breadth-first.
    • FIFO always traveses breadth-first.
  • FOO LIFO and BAR LIFO both traverse the tree depth-first.
    • LIFO always traverses depth-first.
  • When FOO traverses depth-first, it traverses from left-to-right. (FOO LIFO)
  • When BAR traverses depth-first, it traverses from right-to-left. (BAR LIFO)
  • When FOO traverses breadth-first, it traverses from right-to-left. (FOO FIFO)
  • When BAR traverses breadth-first, it traverses from left-to-left. (BAR FIFO)
  • BAR traverses the opposite direction that FOO traverses in and vice-versa.

let run (Target_program bcis) =
 (* run : target_program -> expressible_value *)
  let rec fetch_decode_execute bcis ds =
       (* fetch_decode_execute : byte_code_instruction list -> data_stack -> result_of_execution *)
    match bcis with
    | [] ->
       OK ds
    | bci :: bcis' ->
       (match decode_execute bci ds with
        | OK ds' ->
          fetch_decode_execute bcis' ds'
        | KO s ->
           KO s)
  in match fetch_decode_execute bcis [] with
     | OK [] ->
        Expressible_msg "stack underflow at the end"
     | OK (n :: []) ->
        Expressible_int n
     | OK (n :: _ :: _) ->
        Expressible_msg "stack overflow at the end"
     | KO s ->
        Expressible_msg s;;
